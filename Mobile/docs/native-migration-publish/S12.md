## What to build

Use the existing library/bookmark and reading-history APIs to save/read personal state and resume the correct Chapter/Page across native sessions and the web account.

Scope: Mobile only; reuse existing APIs, business rules and data. Preserve Frontend/Backend/MIT and the shared bridge.

TDD: One observable behavior through public interfaces at a time, using real Mobile code with external-boundary mocks. Record RED → GREEN; refactor only while GREEN. Release-only work verifies device evidence.

## Acceptance criteria

- [ ] Existing library actions and continue-reading operate against the same account/server data as the web client.
- [ ] Chapter/Page progress is restored and stale requests from another identity cannot mutate or delete the current user's history.
- [ ] History/library/resume/account-isolation behavior tests pass.
- [ ] Port the existing Frontend responsive mobile design and navigation using DESIGN.md tokens and original artwork; compare corresponding native/web mobile screens.
