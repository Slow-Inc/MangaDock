# #884 The 48px OCR model runs 3.5-5x faster with cuDNN off — identical reads

- **Date:** 2026-10-22 · **Issue:** #884 · **Method:** warm in-process bench (`doctor_page.py`, 5 corpus-3 pages in ONE process, page 1 discarded as cold), SFX rescue off so the number is the line model alone.
- **Baseline:** `2026-10-22-warm-latency-profile.md` — OCR was 6019 ms of an 11147 ms page (54 %).
- **Defect tied to:** each OCR chunk call costs ~2.2-2.6 s of host-side cuDNN work inside the running pipeline, while the same call repeats at ~0.3 s and runs at ~0.1 s in an isolated process.

| page | lines | OCR before | OCR after | page wall before | page wall after |
|---|---|---|---|---|---|
| Boku no Kokoro p1 | 35 | 4656 ms | **1128 ms** | 11259 ms | **4362 ms** |
| Dungeon ni Hisomu p0 | 22 | 3980 ms | **769 ms** | 6938 ms | **3428 ms** |
| Dungeon ni Hisomu p1 | 23 | 4403 ms | **1311 ms** | 8042 ms | **4372 ms** |
| Horimiya p0 | 72 | 9643 ms | **1930 ms** | 18349 ms | **7660 ms** |

(The cold first page keeps its 5.4-6.2 s detection/model-load cost and is excluded.)

## Traced

| probe | result |
|---|---|
| pipeline, per chunk | 2628 ms first, **291 ms** repeat |
| same model, isolated process | 90-150 ms per call |
| torch profiler, one chunk | **1785 ms self-CPU** in 109 `aten::cudnn_convolution` calls (~16 ms each) |
| larger chunk (16 -> 64) | OCR 3980 -> 2347 ms but **reads changed** (`RIGHT..`->`RIGHT`, a junk `Ξ` inserted) — batch-size numerics, not lossless, rejected |
| pre-warm 10 chunk shapes at load | no effect — the penalty returns per chunk |
| cuDNN off for the whole process | OCR 1523 ms, but LaMa inpainting regressed 3-12x |
| cuDNN off for the OCR model only | OCR **769 ms**, inpainting unchanged |

## Fix

`torch.backends.cudnn.flags(enabled=False)` scoped to the 48px model`s forward (`_cudnn_flags()`); every
other model keeps cuDNN. Windows defaults to off, non-Windows keeps cuDNN (the pathology has only been
measured here). `MIT_OCR_CUDNN=1` / `=0` overrides.
