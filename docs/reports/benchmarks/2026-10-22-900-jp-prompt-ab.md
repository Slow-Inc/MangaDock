# JP→TH prompt A/B: a Japanese-specific prompt ties the shipped Thai prompt (40-line synthetic set)

- **Date:** 2026-10-22 · **Arm:** `tools/prompts/thai_manga_v2_jp.yaml` (shipped v2 template + a Japanese-source
  section: subject omission, sentence-final particles よ/ね/な/かな/ぞ, trailing が/けど/し, です/ます/敬語
  politeness, Japanese idioms, onomatopoeia).
- **Set:** 40 hand-written manga-register Japanese lines in 4 pages of 10 (particles/nuance, politeness
  registers, negation + idioms, fragments/names/SFX/omitted subjects) — a synthetic set because the repo holds
  only two real JP pages (14 segments). Fake `doctor.json` pages feed the existing `translation_ab` harness, so
  arms differ only in the prompt config.

## Result — tie, keep the shipped prompt

| arm | page votes |
|---|---|
| A = shipped Thai prompt (v2) | 2 |
| B = v2 + Japanese-source section | 2 |

Offline, the differences are mixed:

- **B better:** `うるせえな、黙れよ。` -> `น่ารำคาญนัก เงียบปากซะ` (natural rude Thai) vs the base `เงียบๆ หน่อย พูดมากน่ารำคาญ`; `仕方ないなあ` -> `ไม่มีทางเลือกสินะ` (idiomatic) vs base `ก็ทำอะไรมากไม่ได้หรอกนะ`.
- **B worse:** `申し訳ございません。私の不注意でした。` lost the polite `ครับ` the base kept (`ขออภัยเป็นอย่างยิ่ง` vs `ขออภัยเป็นอย่างยิ่งครับ`); `お願いします！` became `ขอโทษจริงๆ` ("sorry") instead of a plea.
- Equally fine elsewhere (onomatopoeia, fragments).

## Decision

No default change — a 2-2 page vote cannot justify retuning the shipped prompt, and the politeness regression
on a keigo line is exactly the class of nuance the section was supposed to protect. The JP arm YAML and the
40-line synthetic set stay as the experiment record for a future attempt (e.g. a politeness-only rule, measured
on its own subset).

## Noted for the record

The judge pair once with an empty/failed gateway response (`JSONDecodeError`); the retry ran clean. Judge noise
remains the limiting factor for translation work at this sample size — page votes with n=4 are weak evidence by
construction.
