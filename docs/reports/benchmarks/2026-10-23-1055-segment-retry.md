# #1055 — opt-in segment-only retry (do not re-translate the whole page for one glitched line)

- **Date:** 2026-10-23 · **Issue:** #1055 · **Files:** `translators/common.py`, tests.

## Problem

Every quality guard re-asks a segment through the translator's repeat loop, and that loop sends the **whole page**
again for each attempt. With guard trigger rate ≈ 1 page in 6 on live traffic, each glitch costs a full extra
translation call (an extra page of tokens).

## Change (opt-in, default off)

`MIT_SEGMENT_RETRY=1`: from the second attempt on, translate only the still-invalid segments and merge their answers
back. Default behaviour is untouched (the whole page is re-sent, preserving page context for the retry).

## Evidence

- Mocked translator, 2-line page where line 2 leaks a script:
  - default: retry prompt carries **2 lines**;
  - `MIT_SEGMENT_RETRY=1`: retry prompt carries **1 line** (on a real 17-line page: ~94 % fewer input lines);
  - the flagged line's new answer is kept in both cases.
- Both shapes are pinned by tests (16 tests in the glitch-retry file).

## Tradeoff (why opt-in)

The retried line loses its page-mates as context and the batch numbering changes for that call — the existing
whole-page retry deliberately gives the model the full page again. Live latency/quality comparison remains open on
#1055 because a guard trigger is intermittent; it needs a larger sample or a forced-failure harness.
