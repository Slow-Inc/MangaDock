# #1047 — opt-in model preload at worker boot (MIT_PRELOAD=1)

- **Date:** 2026-10-23 · **Issue:** #1047 · **Files:** `server/readiness.py`, `manga_translator/mode/share.py`,
  `test/test_readiness.py`.

## Measurement (one real page, loaded host)

| process | first page |
|---|---|
| cold (lazy load on first request) | **19.4 s** |
| preload explicitly (`~1.9 s`) then first page | **14.6 s** |

So the weight load costs ~5 s of the first page; doing it while uvicorn boots moves that cost off the user's
first request. The absolute numbers are noisy on this long-running host (CPU 45-100 %), which is why this is a
directional result, not a tight benchmark.

## Implementation

- `server/readiness.preload_enabled(env)` — pure gate, unit-tested (on only for MIT_PRELOAD=1/true/yes/on).
- `MangaTranslatorShared.start()` creates an asyncio warm task right after `MangaTranslator` is built. It calls
  `_model_lifecycle.preload(Config(), device, 0)` (default model choices = production defaults; request sizes do
  not change which weights load), logs `[share] models preloaded in N ms`, and swallows any failure — preload can
  never break boot.

## Why opt-in

Preloading holds GPU/RAM while the worker is idle and slows boot; default behaviour is unchanged (lazy loading).

## E2E on a real worker (round 76)

Started the worker (`tmp/start_worker.py`, `MangaTranslatorShared`) twice on the same page and measured the **first
HTTP request**:

| arm | preload log | first page (HTTP) |
|---|---|---|
| lazy (MIT_PRELOAD unset) | — | **21.5 s** |
| `MIT_PRELOAD=1` | `[share] models preloaded in 1878 ms` | **18.1 s** |

→ **3.4 s (16 %)** off the first user page on this loaded host; the 1.9 s preload runs while uvicorn boots. Samples are
single-run and the host is busy (CPU 45-100 %), so treat it as directional; the log line proves the hook runs.

The preload timing line is printed to stdout (not `logger.info`) so a plain worker log shows it — otherwise the
message was filtered by the default logging level.
