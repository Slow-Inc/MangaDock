# #1052 — LOST intermittently rendered as หายาก (rare): meaning-changing near-homophone guard

- **Date:** 2026-10-23 · **Issue:** #1052 · **Files:** `translation_quality.py`, `translators/common.py`, tests.

## How it was found

A fresh judge audit of 6 HEAD pages (71 segments, raw mean 1.37/2 — most flags were the judge's known typo noise)
contained one genuine meaning cluster on the Otome page:

| source | shipped Thai |
|---|---|
| `LOST ITEMS.` | `ของหายาก` (**rare items**) |
| `THIS ... IS HOME TO ONE OF THOSE LOST ITEMS.` | `...ของหายากเหล่านั้น` (same swap) |

`หาย` = lost, `หายาก` = rare. The swap is **intermittent**: the audit run shows it, three immediately-following
baseline runs of the same page do not (≈1/4 observed). A corpus scan found only these two unique pairs, both
genuine errors — the pattern is precise, not noisy.

## Fix

`lost_as_rare(dst, query)` (Thai targets): Thai contains `หายาก`, source says `LOST`, source does not say
rare/scarce. Wired into `_is_glitched`, so the existing repeat re-asks that segment with
`LOST means หาย/สูญหาย. หายาก means RARE — do not use it here.`

## Evidence

- Unit tests: both live variants flagged; `ของหาย`, `RARE ITEMS.`, `SCARCE RESOURCES.` untouched.
- Mocked gateway: `ของหายาก` first answer -> one re-ask -> `ของหาย`.
- 4 fresh runs of the affected page with the guard: **0 lost->rare outputs** (the pre-guard rate is intermittent, so
  this is directional; the mock proves the retry path).
- Full suite: see the commit (targeted tests green).

## Related audit notes (no action)

Other audit flags were either judge typo noise (it quotes identical strings as 'wrong') or model-ceiling nuance
(`MORNING`/`Mornin?` flattened to a general greeting, an added `เลย`, `music`->`song`). None has a deterministic
licence that would justify a guard.
